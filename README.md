# ROS 2 Mavros

## Installation

1. Clone the repository.
```bash
git clone https://git.spirirobotics.com/Spiri/services-ros2-mavros.git
```

2. Bring up the container.
```bash
docker compose up --build
```

3. Subscribe to or echo the appropriate topics.

```bash
ros2 topic echo /spiri_mu_1/state
```

## Usage

### Launching
The `docker-compose.yaml` file can be used to configure the MAVROS node. The base command is as follows:

```bash
ros2 launch mavros apm.launch fcu_url:="udp://0.0.0.0:14560@:14555" namespace:="/spiri_mu_1" tgt_system:="1"
```

This is a list of available parameters through `apm.launch`

| Parameter      | Type    | Description                                        |
| -------------- | ------- | -------------------------------------------------- |
| fcu_url        | string  | A [Connection URL](https://github.com/mavlink/mavros/blob/ros2/mavros/README.md#connection-url) that defines the connection between MAVROS and the FCU. |
| gcs_url        | string  | A [Connection URL](https://github.com/mavlink/mavros/blob/ros2/mavros/README.md#connection-url) that defines how MAVROS forwards MAVLink telemetry to a GCS. |
| tgt_system     | int16   | The target system ID. Should be set to the same value as [SYSID_THISMAV](https://ardupilot.org/copter/docs/parameters-Copter-stable-V4.5.7.html#sysid-thismav-mavlink-system-id-of-this-vehicle). |
| tgt_component  | int16   | The target component ID. The default value of `1` refers to the autopilot. Should generally be left unchanged. |
| log_output     | string  | This option is [ignored](https://github.com/mavlink/mavros/issues/1926). No effect. |
| fcu_protocol   | string  | Specifies the MAVLink protocol version to communicate with the FCU. Default (and recommended) value is `v2.0`. |
| respawn_mavros | bool    | Whether the MAVROS node will automatically restart on crash. Default value is `false`. |
| namespace      | string  | Sets the ROS namespace for the MAVROS topics. |

### Plugins

The `apm.launch` launch file also takes into consideration:
  * A list of blacklisted (`plugin_denylist`) or whitelisted (`plugin_allowlist`) plugins defined in [apm_pluginlists.yaml](https://git.spirirobotics.com/Spiri/services-ros2-mavros/src/branch/main/config/apm_pluginlists.yaml) 
  * The configuration settings for the enabled plugins (i.e., plugins not on the denylist) are defined in [apm_config.yaml](https://git.spirirobotics.com/Spiri/services-ros2-mavros/src/branch/main/config/apm_config.yaml)

In general, MAVROS plugins use ROS interface objects in the following ways:
- **Publishers** - Used to listen for specific incoming MAVLink messages to the FCU and convert them into appropriate ROS2 messages.
- **Subscribers** - Used to listen for messages published on specific ROS2 topics which are then converted into the equivalent MAVLink message type to be sent directly to the FCU.
- **Services** - Used to make requests to the FCU via ROS2 service clients.

#### distance_sensor
Distance Sensor plugin. This plugin allows publishing distance sensor data, which is connected to an offboard/companion computer through USB/Serial, to the FCU or vice-versa.

Parameters
```yaml
base_frame_id: base_link
config: "" # Path to config file
```

Config
```yaml
/**/distance_sensor:
  ros__parameters:
    config:
      rangefinder_pub:            # Treat as a publisher node
        id: 0                     # ID of the sensor
        frame_id: "lidar"         # Frame ID for send
        orientation: PITCH_270    
        field_of_view: 0.0        # FOV of the sensor
        send_tf: false            # Defines if a transform is sent or not
        sensor_position: {x:  0.0, y:  0.0, z:  -0.1}
      rangefinder_sub:            # Treat as a subscriber node
        subscriber: true          # True to use rangefinder_sub. False to use rangefinder_pub
        id: 1                     # ID of the sensor
        orientation: PITCH_270
        horizontal_fov_ratio:     # Optional
        vertical_fov_ratio:       # Optional
        covariance:               # Optional
        custom_orientation: {roll: pitch: yaw: } # Optional
```

| Topic | Type | Message Type | Purpose |
| ----- | ---- | ------------ | ------- |
| ~/topic_name | Publisher or Subscriber | [sensor_msgs.Range] | As a publisher, publish [DISTANCE_SENSOR] messages from the onboard distance sensor. As a subscriber, send [DISTANCE_SENSOR] messages to the FCU. |

#### fake_gps
Fake GPS with local position source plugin. Send fake GPS from local position estimation source data (motion capture or vision) to FCU.

Config
```yaml
# fake_gps
/**/fake_gps:
  ros__parameters:
    # select data source
    use_mocap: true               # ~mocap/pose
    mocap_transform: false        # ~mocap/tf instead of pose
    mocap_withcovariance: false   # ~mocap/pose uses PoseWithCovarianceStamped Message
    use_vision: false             # ~vision (pose)
    use_hil_gps: true
    gps_id: 4
    # origin (default: Zürich)
    geo_origin.lat: 47.3667       # latitude [degrees]
    geo_origin.lon: 8.5500        # longitude [degrees]
    geo_origin.alt: 408.0         # altitude (height over the WGS-84 ellipsoid) [meters]
    eph: 2.0
    epv: 2.0
    horiz_accuracy: 0.5
    vert_accuracy: 0.5
    speed_accuracy: 0.0
    satellites_visible: 6     # virtual number of visible satellites
    fix_type: 3               # type of GPS fix (default: 3D)
    tf.listen: false
    tf.send: false            # send TF?
    tf.frame_id: "map"        # TF frame_id
    tf.child_frame_id: "fix"  # TF child_frame_id
    tf.rate_limit: 10.0       # TF rate
    gps_rate: 5.0             # GPS data publishing rate
```

| Topic | Type | Message Type | Purpose |
| ----- | ---- | ------------ | ------- |
| ~/mocap/pose | Subscriber | geometry_msgs.PoseStamped | Send [HIL_GPS] to the FCU if **use_hil_gps** is `True` or [GPS_INPUT] if **use_hil_gps** is `False`. Use MoCap data in PoseStamped message. Toggled by setting **use_mocap**. |
| ~/mocap/tf | Subscriber | geometry_msgs.TransformStamped | Send [HIL_GPS] to the FCU if **use_hil_gps** is `True` or [GPS_INPUT] if **use_hil_gps** is `False`. Use MoCap data in TransformStamped message. Toggled by setting **use_mocap**. |
| ~/mocap/pose_cov | Subscriber | geometry_msgs.PoseWithCovarianceStamped | Send [HIL_GPS] to the FCU if **use_hil_gps** is `True` or [GPS_INPUT] if **use_hil_gps** is `False`. Use MoCap data in PoseWithCovarianceStamped message. Toggled by setting **use_mocap**. |
| ~/vision | Subscriber | geometry_msgs.PoseStamped | Send [HIL_GPS] to the FCU if **use_hil_gps** is `True` or [GPS_INPUT] if **use_hil_gps** is `False`. Use MoCap data in PoseStamped message. Toggled by setting **use_vision**. |

#### landing_target
Landing target plugin. This plugin is intended to publish the location of a landing area captured from a downard facing camera to the FCU and/or receive landing target tracking data coming from the FCU.

```yaml
/**/landing_target:
  ros__parameters:
    frame_id: "landing_target_1"
    listen_lt: true
    mav_frame: "LOCAL_NED"
    land_target_type: "VISION_FIDUCIAL"
    target_size.x: 1.0            # [meters]
    target_size.y: 1.0
    image.width: 640              # [pixels]
    image.height: 480
    camera.fov_x: 2.0071286398    # default: 115 [degrees]
    camera.fov_y: 2.0071286398
    camera.focal_length: 2.8      # ex: OpenMV Cam M7: 2.8 [mm]
    tf.send: true
    tf.listen: false
    tf.frame_id: "landing_target"
    tf.child_frame_id: "camera_center"
    tf.rate_limit: 10.0
    target_size: {x: 0.3, y: 0.3}
```

#### odometry
Odometry plugin. Sends odometry data to the FCU estimator and publishes odometry data that comes from the FCU. This plugin is following ROS REP 147. Pose is expressed in parent frame (Quaternion rotates from child to parent). The twist is expressed in the child frame.

Parameters
```yaml
fcu.odom_parent_id_des: "map"
fcu.odom_child_id_des: "base_link" 
fcu.map_id_des: "map" 
```

| Topic | Type | Message Type | Purpose |
| ----- | ---- | ------------ | ------- |
| ~/in | Publisher | mavros_msgs.Odometry | Publish [ODOMETRY] messages. Callback for mavlink ODOMETRY messages sent from the FCU. According to the mavlink specification, all quantities are for the child frame (fcu_frd), expressed in the parent frame (local_origin_ned). To be compliant with ROS REP 147 for the published `nav_msgs/Odometry`, the data is appropriately transformed and published. Frames for the publish message should be specified in the parameters. |
| ~/out | Subscriber | mavros_msgs.Odometry | Send [ODOMETRY] messages. The frame_ids in the odom message have to fit the frames that are are added to the tf tree. The odometry message gets rotated such that the parent frame is `odom_ned` and the child frame is `base_link_frd`. |

#### wheel_odometry
Wheel odometry plugin. This plugin allows computing and publishing wheel odometry coming from FCU wheel encoders. Can use either wheel's RPM or WHEEL_DISTANCE messages (the latter gives better accuracy).

> **Note:** This plugin is specific to APM.

Config
```yaml
/**/wheel_odometry:
  ros__parameters:
    count: 2                      # number of wheels to compute odometry
    use_rpm: false                # use wheel's RPM instead of cumulative distance to compute odometry
    wheel0: {x: 0.0, y: -0.15, radius: 0.05}  # x-, y-offset (m,NED) and radius (m)
    wheel1: {x: 0.0, y:  0.15, radius: 0.05}  # x-, y-offset (m,NED) and radius (m)
    send_raw: true                # send wheel's RPM and cumulative distance (~/wheel_odometry/rpm, ~/wheel_odometry/distance)
    send_twist: false             # send geometry_msgs/TwistWithCovarianceStamped instead of nav_msgs/Odometry
    frame_id: "map"               # origin frame
    child_frame_id: "base_link"   # body-fixed frame
    vel_error: 0.1                # wheel velocity measurement error 1-std (m/s)
    tf.send: true
    tf.frame_id: "map"
    tf.child_frame_id: "base_link"
```
| Topic | Type | Message Type | Purpose |
| ----- | ---- | ------------ | ------- |
| ~/rpm | Publisher | mavros_msgs.WheelOdomStamped | Publish [RPM] messages. Toggled by setting **send_raw**. |
| ~/distance | Publisher | mavros_msgs.WheelOdomStamped | Publish [WHEEL_DISTANCE] messages. Toggled by setting **send_raw**. |
